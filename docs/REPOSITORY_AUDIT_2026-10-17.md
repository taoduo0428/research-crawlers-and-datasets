# 2026-10-17 仓库检查记录

> 本文保留最初整理批次的历史审计信息；后续针对整个 GitHub 仓库再次执行的 1,393 项离线测试及修复结果，请看 [全仓库离线验收记录](REPOSITORY_VALIDATION_2026-10-17.md)。现网采集和历史合规仍有独立验收要求。

这份记录是给后来接手项目的人看的：**哪些文件已经检查过，数据有什么坑，哪些功能还没真正跑通。** 检查的是当时整理到 GitHub 的源码和数据，不包括重新登录各个网站采集。

仓库后来已设为 Public。下面关于「不建议公开」的结论，是**对数据和 Git 历史风险的判断**，不是在说仓库现在仍是 Private。

## 已经确认的事

- 当时的 Python 源码语法解析没有报错（253 个文件）。这只能说明语法没坏，不等于所有程序都能运行。
- 外包/招聘引擎选定的离线测试 193 项、Facebook 97 项、Keep 新增测试 4 项通过。没有因此宣称实机采集通过。
- Keep 第一阶段 206 份共享 JSON 已改成字段白名单；用户、动态、评论三张表能从发布的 JSON 重新生成。
- 修复前的 Keep 数据仍可能留在旧提交里。是否能公开再分发 B站字幕、影评等第三方内容，也还没有核实完。

## 接下来最好处理的事

**最着急的是历史和授权。** 旧 Keep 版本还在 Git 历史里，修最新文件不能替代清理旧提交。字幕、影评及其他第三方材料能否公开，仍需专门确认。仓库里一些引入的组件也要核对上游许可证，不能一概改成某个开源许可证。

**研究数据方面：** 前程无忧缺完整原始层，BOSS ID 归档缺 JD；猎聘还没有逐条对好最终表和源表。一品威客的发布日期证据要分级，猪八戒要补详情。Amazon 月销量有 6,134 行为空，评论留评率有 130,399 行为空；销量相同 ASIN/月有 28 条冲突、月评论有 1 条冲突，不能直接覆盖其中一个版本。

**运行方面：** 这里只做了选定的离线测试。B站、豆瓣、Keep 第一阶段、Amazon 旧脚本、Facebook 设备端，以及七站的现网采集，都没有在这轮重新完成全流程验收。

GitHub Actions 自动校验目前还是 `docs/optional-ci-workflow-template.yml` 模板，没有真正启用。`tools/build_repository.py` 则是维护者给自己的发布脚本，不是新同学的安装入口。

## 怎么自己检查

从仓库根目录开始：

```bash
git lfs pull
python tools/verify_release.py
python tools/normalize_keep.py --input projects/social/keep/data/phase1_anonymized --output ../keep-rebuilt
```

外包、招聘代码在 `projects/market-platform/`；先运行 `python run.py --help`。Facebook 先按平台安装说明准备依赖，再选明确不需要设备、网络的测试。不要把一次单元测试通过理解成「网站现在能完整采下来」。

**结论：文件完整性和主要离线测试基本过关；数据溯源、现网采集、历史安全和第三方授权还没全部解决。** 后续谁处理某个问题，在提交记录中说明改动和验证情况就可以了。
