# 公开和使用这些数据，要注意什么

**仓库目前已经是 Public，但还有两件没处理完的事：旧 Git 历史，以及部分数据的转载权限。** 公开状态只是 GitHub 的一个设置，不等于这些问题已经解决。

## 1. 旧历史不会因为修了文件就消失

Keep 第一阶段最早上传过一批脱敏不彻底的 JSON，里面有媒体链接和一些未清理的字段。后来已改成只保留研究必需字段的匿名摘要，但之前的 Git 提交仍可能被找到。

在独立清理、核实旧历史前，别把仓库说成「已经彻底去除所有历史敏感信息」。有权限处理仓库的维护者应另行审查历史和 LFS 对象；不要未经评估直接重写历史或破坏其他成员正在使用的分支。

## 2. 第三方内容不是想公开就能公开

B站字幕、豆瓣影评、招聘与外包网站的页面正文，可能涉及著作权、网站协议或个人信息。仓库能下载，不代表取得了转载或转售授权。对外发布数据集或论文附件前，需要确认对应内容是否允许分享；不能确定时优先公开代码、字段说明和汇总统计。

## 3. 哪些原始材料没有放进仓库

- Facebook：完整 MITM 抓包、`runs/` 原始日志、账号会话、证书、APK、模拟器资料和用户身份明文。
- Keep：原始用户/动态 JSON、昵称头像、评论正文、媒体 URL 和登录态。仓库保留的是字段最小化后的 206 份匿名 JSON，以及第二阶段三张整理表。
- Amazon / Jiimore：历史 ZIP、部分原始网页和登录 Cookie。
- 各项目：`.env`、个人账号密码、浏览器 Profile、虚拟环境、缓存和本地运行状态。

旧脚本可能曾写过登录凭据。仍在使用的账号应更换这些凭据，并只从环境变量或本地安全配置读取，不要再写进源码。

## 4. 数据本身有哪些限制

一品威客有 376 条没有实际发布日期，只能拿站点地图更新时间作候选；猪八戒的 7,082 条主要来自列表页，不能当完整详情。BOSS 的 ID 归档没有完整 JD，前程无忧的全量原始层还没找回。

B站多批字幕有重叠且有缺字幕。Amazon、Jiimore 和 SellerSprite 的时间序列覆盖范围不同，部分月份缺值。Facebook 任务显示 `completed` 不等于一定采到完整名单。豆瓣目前是 6 部电影的小样本。

这些问题不妨碍做研究，但写分析结论时必须把限制交代清楚。更多逐项记录在[全仓库审计](REPOSITORY_AUDIT_2026-10-17.md)。

## 5. 关于能不能直接运行

本仓库没有在 2026-10-17 重新对全部网站做真实抓取，也没有证明所有旧脚本都适配今天的接口。先读对应 README、安装依赖、跑离线测试，再做自己的联网验收。
