# 课题组成员从哪开始

新接手的同学按下面这个顺序来，基本不会走错。

## 第一次进仓库

1. 先读[总 README](../README.md)，找到自己负责的网站。
2. 克隆仓库，运行 `git lfs pull`，再运行 `python tools/verify_release.py`。先确认数据没有缺。
3. 打开那个网站的 README：看入口脚本、已有数据和没解决的问题。
4. 如果只是做数据分析，先用 `data/`；不需要为了看 CSV 就把爬虫启动起来。
5. 如果要继续采集，单独建 Python 虚拟环境，安装那个项目的依赖，跑离线测试后再做小样本试跑。

## 修改代码怎么交

尽量一次只改一件事。提交时说明「改了什么、为什么改、怎么验证」；涉及网页采集的，最好写上当时测试的页面或 API 变化。不要把临时调试文件和本机环境一起提交。

## 新增数据怎么交

保留原始记录（前提是适合共享），另做清洗结果。交数据时至少写清楚：

- 采集日期和网站；
- 采了哪些类别、有无时间或数量限制；
- 主键是什么，删掉了哪些无效记录；
- 哪些字段为空，哪些数字只是估计；
- 从原始层生成最终表的脚本或步骤。

大文件按仓库已有的 Git LFS 规则提交。改过已纳入清单的文件后，更新 `metadata/data-manifest.json` 或 `source-manifest.json` 里的哈希，再跑 `python tools/verify_release.py`。

## 不要上传这些东西

真实账号、Cookie、`.env`、浏览器 Profile、登录证书、用户身份明文、未审核的抓包、模拟器数据和个人设备路径里的敏感文件都不要提交。以前脚本里的认证信息不能直接复用，先换成自己机器上的环境变量。

仓库目前已经公开，但这不意味着所有第三方文本或个人信息都适合再次传播。准备对外分享数据集时，先看[安全说明](SECURITY_AND_LIMITATIONS.md)。
