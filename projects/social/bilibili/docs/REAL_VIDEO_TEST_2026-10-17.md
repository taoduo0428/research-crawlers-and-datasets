# B站字幕：2026-10-17 真实视频测试

之前的结论是「视频信息能抓，字幕只能用历史 CSV」。这次在 B站重新挑选了 10 条公开视频测试，找到了旧程序把实时字幕误判为空的原因，并真正抓到了新的字幕正文。

测试时没有使用登录 Cookie，也没有下载视频或音频。这里只记录测试结果，不公开保存这些视频的完整字幕内容。

## 做了什么

先从 B站找到了 10 条真实视频：有的标题或简介写着 CC、AI 字幕，有的是开源字幕项目曾经用来验证的案例。

- **视频信息：10/10 成功。** 当前公开接口能返回 BV、AV、CID、标题、UP 主、播放量等字段。
- **字幕轨道：10 条里有 5 条至少一次返回了真实字幕轨道。** 以前的 Protobuf 解析漏掉了最外层 data 字段，所以连存在的轨道也判成空。
- **字幕正文：多次单独测试中，双语英语视频、采访、字幕工具教程、一人公司视频都真正下载过字幕 JSON；但有些视频连续两次请求结果不同。**
- **完整 CSV 流程：从中选 5 条，把视频信息、字幕正文合进同一张 27 列 CSV。5/5 刷新当前视频信息，3/5 新抓到字幕，另外 2 条没有当场获取到字幕轨道。**

## 原来是哪儿出了问题

1. B站新版字幕信息接口 `/x/v2/subtitle/web/view` 返回 **Protobuf 二进制**，结构是「最外层字段 1 → 内部重复字段 3（字幕轨道）」。旧脚本直接从最外层找字段 3，因此把真正存在的字幕轨道漏掉了。
2. 新接口返回的有些字幕 URL 使用 `subtitle.bilibili.com` 的播放器编码地址。这不是可直接访问的下载链接；程序现在按播放器的地址编码格式还原到 `aisubtitle.hdslb.com`，并检查目标是否在允许的字幕域名和路径中。
3. 旧的 `/x/player/v2` 在匿名情况下常会返回空数组；现在先核对签名播放器接口和新 Protobuf 接口，不会单凭旧接口空数组就断言没字幕。
4. 新版工具仍会在取不到实时字幕时，尝试从历史 CSV 补全；**每一行的「字幕来源」会分别写「实时接口」或「历史CSV」**，不能把补全内容算进实时采集成功数。

没有将 Cookie、字幕临时签名 URL、字幕正文写入这份报告。

## 想在自己的电脑上重试

在总仓库根目录运行：

~~~bash
python -m pip install requests
python projects/social/bilibili/tools/collect_combined.py --bvid BV1TgjwzGEuG --bvid BV15qQwB4EZ9 --output ../bili_live_test.csv
~~~

输出放在仓库外，不会覆盖历史数据。检查 CSV 的 `字幕来源`：

- `实时接口`：这次真的下载到了新字幕文本。
- `历史CSV：...`：只合并了以前的数据。
- 空：这次没有字幕正文，`字幕状态` 会尽量说明原因。

**是否需要 Cookie？** 这次三个实时字幕成功案例均无需登录。但某些视频的轨道和字幕正文仍可能需要有效会话；不建议把浏览器完整 Cookie 发给其他人或提交 Git。

回归测试：

~~~bash
python -m unittest discover -s projects/social/bilibili/tests -p test_combined.py -v
~~~
