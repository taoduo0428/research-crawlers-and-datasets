# Keep：两阶段采集与研究整理

本项目来自本地原始资料，分为**第一阶段抓包**与**第二阶段清洗整理**。仓库只包含经过字段最小化的科研共享版；**不包含原始抓包、可识别用户的资料、动态正文、图片/视频链接、登录态或账号凭据**。

## 1. 第一阶段：抓包 / 原始响应

原始工作目录曾保存 101 份用户 JSON 与 105 份动态 JSON；它们保留在项目持有者本机，没有上传。

共享目录：

- `data/phase1_anonymized/profiles/`：101 个匿名资料摘要 JSON。
- `data/phase1_anonymized/activities/`：105 个匿名动态摘要 JSON。

**发布结构是字段白名单投影，不是原始 Keep HTTP 响应的完整复制。** 仅保留需要参与第二阶段关联的假名 ID、有限的用户属性、动态类型/状态/互动计数与评论数量/关联结构，所有未知 API 字段默认丢弃。字段结构以这两个目录中的文件为准。

目前没有找到可在新机器上一键重现第一阶段网络抓包的完整程序，仓库也不提供任何爬取用 Cookie、代理证书或原始 Flow。历史“八爪鱼采集器”快捷方式不能作为可移植的源码。第一阶段的原始数据采集方法须由有权限的成员另外验收，不应把第二阶段脚本称为抓包程序。

## 2. 第二阶段：归一化数据

不需要网络或 Keep 账号，Python 3.11+ 即可。请先在**仓库根目录**运行：

`python tools/normalize_keep.py --input projects/social/keep/data/phase1_anonymized --output ../keep-rebuilt`

然后运行 `python tools/verify_release.py` 检查仓库发布数据，或比较 `../keep-rebuilt/` 与 `projects/social/keep/data/phase2/` 的文件哈希。

| 输出 | 行数 | 唯一键 | 备注 |
|---|---:|---|---|
| `data/phase2/profiles.csv` | 100 | `profile_id` | 匿名用户属性 |
| `data/phase2/posts.csv` | 1,050 | `post_id` | 原始 1,146 条动态按 ID 合并 |
| `data/phase2/comments.csv` | 1,692 | `comment_id` | 示例评论关联索引，无评论正文 |

三表通过 `profile_id`、`author_id`、`post_id` 关联。动态及评论已经分开计数，不能把历史旧 CSV 的 2,838 行称为 2,838 条不同动态。

整理脚本采用**固定文件顺序、重复动态确定性合并、稳定的匿名评论 ID**，可从发布版第一阶段数据重建字节一致的第二阶段 CSV。请不要直接使用脚本默认输出覆盖已提交数据，建议始终指定单独的 `--output`。

### 历史兼容提示

2026-10-17 的安全修复替换了旧版匿名评论 ID，并重新发布了第一阶段白名单文件。**不要把旧提交中的 Keep ID 与新版本跨提交连接。** 匿名映射密钥不随仓库发布，也无法用共享数据还原真实账号。旧版 Git 历史仍应视作不适合公开的资料，公开前需要独立完成历史清理及复核。

## 3. 历史代码与使用限制

`source/phase2/` 保留历史 Python 整理脚本供比较。其旧路径硬编码、动态与评论混表等问题尚未全部修复；课题组复现请使用仓库根目录的 `tools/normalize_keep.py`。

原始用户资料、HTTP 响应、图片链接及评论文本属于敏感或第三方内容。即使本仓库为 Private，使用时也应遵守研究伦理和数据访问范围。不要尝试重新识别匿名用户。
