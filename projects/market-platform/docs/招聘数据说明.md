# 招聘数据说明

## 数据范围

完整元数据交付包含 BOSS、前程无忧和猎聘三个招聘网站；初步处理结果只包含前程无忧和猎聘。职业分类均来自网站官方职业目录，不是根据岗位标题人工推断，也没有用标题代替分类。

数据分为两层：

- `outputs/招聘--完整数据`：BOSS、前程无忧、猎聘三站的基础完整元数据。猎聘已合并取得的 JD，未取得的仍保留空值。
- `outputs/招聘--最终结果`：只包含前程无忧和猎聘，并只保留有 JD 的岗位，字段为职位、JD、薪资、一级分类、二级分类、三级分类。

旧交付目录已可逆归档到项目回收站；详情补充、worker 输出和断点迁至 `.crawler-state/recruitment-details`，不占用最终交付目录。

## 字段口径

清洗结果字段如下：

| 字段 | 含义 | 处理方式 |
| --- | --- | --- |
| 职位 | 岗位名称 | 去除首尾空白、合并重复空格 |
| JD | 岗位职责和任职要求原文 | 统一换行、去除 HTML 标签、控制字符和多余空行；不进行摘要或改写 |
| 薪资 | 网站展示的薪资原文 | 保留区间、单位和计薪周期，只统一空白和 `K` 的大小写 |
| 一级分类 | 官方职业目录第一级 | 保留网站原分类 |
| 二级分类 | 官方职业目录第二级 | 保留网站原分类 |
| 三级分类 | 官方职业目录第三级 | 保留网站原分类 |

前程无忧 JD 来自其岗位搜索响应中的官方职位描述字段；猎聘 JD 来自岗位详情页。完整元数据的 JSONL 保留嵌套的 `metadata`、`price_evidence`、分类关联等原始结构；CSV 和 XLSX 中的嵌套对象以 JSON 文本保存。

## 文件位置

```text
outputs/招聘--完整数据/
  BOSS/岗位数据.jsonl|csv|xlsx
  前程无忧/岗位数据.jsonl|csv|xlsx
  猎聘/岗位数据.jsonl|csv|xlsx

outputs/招聘--最终结果/
  前程无忧/岗位数据.jsonl|csv|xlsx
  猎聘/岗位数据.jsonl|csv|xlsx
  处理统计.json
```

JSONL 适合程序读取并完整保留嵌套元数据；CSV 适合常规数据处理；XLSX 适合直接查看。完整层的 JSONL 和 CSV 保留 JD 原始换行，XLSX 受表格格式影响统一为 `LF` 换行，并把以 `=` 开头的文本强制保存为普通文本，避免被当成公式。三站完整层与两站最终层的三种格式均已核对，XLSX 写入没有出现超过单元格长度上限而被截断的情况。

## 数据边界

本数据是按官方职业分类进行的有界采集，不等同于三个平台在某一时刻的全部在线岗位。BOSS 仅保留基础元数据，未进入本次有 JD 的初步处理结果。相同岗位可能被网站关联到多个职业路径；完整元数据中保留平台返回的分类关联信息，清洗表使用该记录的一级、二级、三级主分类。薪资保留源站原文，未统一换算成年薪或月薪，后续计算平均值前应先按计薪周期单独标准化。
