- `C:\Users\lenovo\Desktop\个人知识库\项目\爬虫\亚马逊\新建文件夹\`

另一个近似副本在 `个人知识库\项目\亚马逊\另一份以协作者姓名命名的同级目录\`。那边保留了不同版本的 Amazon 脚本和评论采集代码，**不是这次总仓库电商数据的直接主来源**，需要再核对后才能决定是否合并。

## 先说结论

**不建议选其中一个删掉另一个。** 两个文件夹共用相同的 1,999 个 ASIN，也有大量完全相同的脚本，但保存的采集结果不同：

- `成功` 主要有**大规模的 Jiimore / SellerSprite 时间序列**；
- `新建文件夹` 主要保留了**Amazon 商品主表、商品标签、Keepa 历史曲线**；
- `新建文件夹` 里较小的月销量和月评论文件，全部都在 `成功` 的对应大表内，不应该重复追加。

| 原文件 | `成功` | `新建文件夹` | 怎么用 |
| --- | ---: | ---: | --- |
| `Data/ASIN.txt` | 同一文件 | 同一文件 | 共同商品清单，不必重复导入 |
| `Data/jiimore/asin.csv` | 1,999 行 | 1,999 行 | SHA-256 完全相同 |
| `Data/jiimore/jiimore.csv` | **117,049 行** | 无 | 周点击等历史指标，以 `成功` 为主 |
| `Data/sellersprite/monthly_sales.csv` | **66,871 行** | 907 行 | 小表 907/907 行都能在大表逐行找到 |
| `Data/sellersprite/reviews.csv` | **178,785 行** | 1,653 行 | 小表 1,653/1,653 行都能在大表逐行找到 |
| `Data/amazon/goods_infos.csv` | 无已保存结果 | **2,006 行** | Amazon 商品基本信息，1,999 个非空不同 ASIN |
| `Data/amazon/customers_say_tags.csv` | 无已保存结果 | **8,533 行** | 商品标签，涉及 1,342 个 ASIN |
| `Data/sellersprite/keepa.csv` | 无 | **25,824 行** | 仅涉及 18 个 ASIN，不能当全部商品都有历史曲线 |

总仓库里的 `data/` 已经按这个原则整理：**商品与标签取 `新建文件夹`，点击与大规模销量、评论取 `成功`，Keepa 取 `新建文件夹`。**

## 脚本是不是一样的？

两边各有 7 份 Python 脚本。对原始文件逐字节比较：

- `jiimore.py`、`jiimore1.py`、`sellersprite.py`：**完全一样**；
- `amazon.py`：主体非常接近，但 `新建文件夹` 多了读取已有 ASIN 的处理；
- `Amazon1.py`、`amazon2.py`：实现差别较大，两边各有自己的商品抓取/补字段办法；
- `sellersprite1.py`：相似但不相同，`成功` 多了读取已有 ASIN 的逻辑。

**原来 GitHub 的 `source/current/` 来自「成功」，`source/legacy/` 来自「新建文件夹」。这只是整理时给的目录名，并没有证据证明「新建文件夹」更旧或「成功」里的每个脚本都更好用。** 读源代码时应按这两个原文件夹分别理解。

另一个 `另一份以协作者姓名命名的同级目录` 分支跟这里有很多重复，但其 `成功/amazon.py` 等文件明显不同，并且有 `amazon_reviews_only.py`。这一支可能是并行实验，应先查来源和数据再决定是否添加到发布仓库。

## 哪些已经验证，哪些没有

目前核实过：

1. 两个原始文件夹的 Python 源码均能通过静态语法解析；
2. 上面所有 CSV 的行数、ASIN 范围和重复文件关系；
3. `成功` 的大表与 `新建文件夹` 的销量/评论小表之间，记录完全包含，没有新增行。

**尚未验证的：** 在今天的 Amazon、Jiimore、SellerSprite 网站重新登录、采集和保存结果。旧脚本依赖浏览器和账号，不能根据文件夹名叫「成功」就认为当前可以直接运行。原目录的 `jiimore.py` 重试代码引用 `time.sleep()` 却没有导入 `time`。这次已经在总仓库的 `source/current/jiimore.py` 与 `source/legacy/jiimore.py` 补上导入，但还没有实测登录网站；**原电脑上的文件没有修改**。Amazon 商品表的 `amazon global shipping` 目前仍然全部为空，不能说那一列已经补采完成。

## 课题组拿数据怎么做

先用 `data/amazon/products.csv` 做商品主表，以 `ASIN` 匹配 `data/jiimore/weekly_clicks.csv`、`data/sellersprite/monthly_sales.csv` 和 `data/sellersprite/monthly_reviews.csv`。月度表还需要 `月份`，不能仅按 `ASIN` 一列合并。

四张主表共同拥有 **1,998 个 ASIN**，但不是所有商品都覆盖相同的月份。月销量/评论存在缺失、重复键和少量不同值的冲突，建模之前先确定去重与缺失规则。

这些都是历史数据，不代表现在的销售情况。

## 重新生成分析表的方法

为了避免两个版本再次混在一起，总仓库新加了[离线整理工具](../tools/review_data.py)和[数据质量检查结果](数据质量检查_2026-10-17.md)。它从已发布的七张 CSV 开始，不依赖原电脑绝对路径，不调用任何线上站点，也不修改原始数据。

月销量和月评论按 `ASIN + 月份` 合并，周点击保留自己的 `ASIN + 日期` 粒度；冲突不能自动覆盖。两个源目录中的重复小表不额外导入。
