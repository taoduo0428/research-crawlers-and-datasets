## 旧脚本为什么不能直接运行

对本机 Python 环境检查：

- `requests`、`beautifulsoup4`、`pandas` 已安装；
- `DrissionPage`、`ddddocr`、`selenium` 未安装；
- 旧脚本写死的本地代理 `127.0.0.1:7890` 当前没有服务监听。

此外，`source/current/amazon2.py` 的验证码处理会尝试自动识别并填写验证码，且默认写入 `data/amazon/`；SellerSprite 旧脚本也会直接向 CSV 追加。**这些旧脚本没有被直接批量运行。** 这次另写了一份只读的小样本测试工具，既不会自动处理网站挑战，也不触碰已经发布的数据。

## 你自己怎么复测

在总仓库根目录打开终端：

~~~bash
python -m pip install requests beautifulsoup4

# 一个 ASIN，依次测试商品页面、月评论、Keepa、月销量、Jiimore
python projects/commerce/amazon-jiimore/tools/live_probe.py --asin B005G9E98O

# 只测试 Amazon 当前公开的商品页面
python projects/commerce/amazon-jiimore/tools/live_probe.py --asin B08H3JPH74 --site amazon

# 只测试卖家精灵当前月评论数据
python projects/commerce/amazon-jiimore/tools/live_probe.py --asin B09XMYFTB7 --site sellersprite_reviews
~~~

输出是 JSON 摘要。每种数据都有 `success` 和 `status`：

- `success: true` 表示验证过必要的字段，不是单看 HTTP 200。
- `status: login_required` 表示需要登录；脚本不会自行登录。
- `status: no_usable_data` 表示接口虽有响应，但没有我们要的数据。
- `status: http_error` 表示网站返回非 200，不会解验证码或尝试绕过限制。

默认每次只查 1 个 ASIN；最多可以重复 `--asin` 三次。每个请求之间有限速。**默认不产生文件**；如要保存 JSON 测试报告，可加 `--output ../amazon_live_probe.json`，程序不允许将报告直接保存到 Git 仓库里。

python tools/verify_release.py
